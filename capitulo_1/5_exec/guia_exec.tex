\section{Motivación}
La función \texttt{fork()} nos permite duplicar un proceso existente, pero ambos procesos continúan ejecutando el mismo código fuente. ¿Qué ocurre si deseamos que el nuevo proceso ejecute un programa completamente diferente (como \texttt{ls}, \texttt{grep} o un binario compilado de C)? Para este propósito, los sistemas POSIX proveen la familia de funciones \texttt{exec()}.

\section{Idea Fundamental}
Las llamadas al sistema de la familia \texttt{exec()} no crean un nuevo proceso. En su lugar, \textbf{reemplazan la imagen de memoria del proceso actual} por un nuevo programa ejecutable. El identificador de proceso (PID) se mantiene exactamente igual, pero el segmento de código, datos, pila y heap son destruidos y sustituidos por los del nuevo programa.

\section{Variantes de la Familia exec()}
Existen diferentes funciones según cómo reciben la ruta del ejecutable y los argumentos:
\begin{itemize}
    \item \textbf{l (lista):} Los argumentos se pasan como una lista de parámetros terminada en \texttt{NULL} (ej. \texttt{execl}, \texttt{execlp}).
    \item \textbf{v (vector):} Los argumentos se pasan en un arreglo (\textit{vector}) de cadenas terminado en \texttt{NULL} (ej. \texttt{execv}, \texttt{execvp}).
    \item \textbf{p (PATH):} Busca el ejecutable en las rutas definidas en la variable de entorno \texttt{PATH} (ej. \texttt{execlp}, \texttt{execvp}).
    \item \textbf{e (entorno):} Permite pasar un arreglo personalizado de variables de entorno (ej. \texttt{execve}).
\end{itemize}

\section{Sintaxis Básica}
\begin{lstlisting}[numbers=none]
#include <unistd.h>

// Uso con vector y busqueda en PATH:
char *args[] = {"ls", "-l", "/tmp", NULL};
execvp("ls", args);

// Uso con lista:
execlp("ls", "ls", "-l", "/tmp", (char *)NULL);
\end{lstlisting}

\section{Ejemplo Mínimo Funcional}
\begin{lstlisting}
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork failed");
        return 1;
    } else if (pid == 0) {
        // Codigo del Hijo: Reemplazar imagen por '/bin/ls'
        printf("[HIJO PID %d] Ejecutando execvp...\n", getpid());
        char *args[] = {"ls", "-la", NULL};
        execvp("ls", args);

        // Si execvp tiene exito, ESTA LINEA NUNCA SE EJECUTA
        perror("execvp failed");
        exit(1);
    } else {
        // Codigo del Padre: Esperar a que el hijo termine
        printf("[PADRE PID %d] Esperando al hijo (PID %d)...\n", getpid(), pid);
        wait(NULL);
        printf("[PADRE PID %d] El hijo finalizo exitosamente.\n", getpid());
    }

    return 0;
}
\end{lstlisting}

\section{Explicación Paso a Paso}
\begin{enumerate}
    \item \texttt{fork()}: Crea un proceso hijo duplicando la memoria del padre.
    \item \texttt{execvp("ls", args)}: En el proceso hijo, sustituye su espacio de direcciones por la imagen binaria del comando \texttt{ls}.
    \item \textbf{Punto de no retorno:} Si la llamada a \texttt{execvp} es exitosa, el código del programa original tras la línea del \texttt{execvp} desaparece por completo y el control se entrega a la función \texttt{main} del comando ejecutado.
    \item Si \texttt{execvp} falla (por ejemplo, si el comando no existe), retorna $-1$ y se ejecuta la siguiente línea (\texttt{perror}).
\end{enumerate}

\section{Qué Ocurre en Memoria}
Al invocar cualquier función de la familia \texttt{exec}:
\begin{itemize}
    \item Los segmentos de Código (\textit{Text}), Datos (\textit{Data}), BSS, Pila (\textit{Stack}) y Heap son destruidos.
    \item El Kernel lee el encabezado ELF del ejecutable especificado y carga los nuevos segmentos en memoria.
    \item El contador de programa (PC) se inicializa en el punto de entrada del nuevo ejecutable.
    \item \textbf{Propiedades preservadas:} El PID, el PPID, los descriptores de archivos abiertos (salvo que tengan la bandera \texttt{FD\_CLOEXEC}) y las credenciales de usuario se mantienen intactos.
\end{itemize}

\section{Patrones Comunes de Uso}
El patrón clásico en sistemas operativos UNIX es la combinación \textbf{\texttt{fork()}} + \textbf{\texttt{exec()}} + \textbf{\texttt{wait()}}, el cual forma la base de la ejecución de comandos en cualquier emulador de Shell o terminal.

\section{Errores Comunes}
\begin{itemize}
    \item \textbf{Olvidar terminar la lista/arreglo con \texttt{NULL}:} Tanto el vector de argumentos de \texttt{execv} como la lista de \texttt{execl} requieren obligatoriamente un apuntador \texttt{NULL} al final. De lo contrario, causará acceso inválido a memoria (\textit{Segmentation Fault}).
    \item \textbf{Escribir código despues de \texttt{exec}:} Pensar que la función \texttt{exec} retornará al código fuente original tras completar el nuevo programa. Recordar que \texttt{exec} solo retorna si ocurre un error.
\end{itemize}

\section{Buenas Prácticas}
\begin{itemize}
    \item Colocar siempre una llamada a \texttt{perror()} y \texttt{exit(EXIT\_FAILURE)} inmediatamente después de la invocación a \texttt{exec()}, para gestionar adecuadamente posibles errores de carga.
    \item Usar \texttt{execvp} cuando se ejecuten comandos estándar del sistema instalados en las rutas habituales del sistema.
\end{itemize}

    \item Investigue \texttt{execve} y escriba un programa que ejecute un binario sencillo con un entorno personalizado que contenga una variable \texttt{TURNO}.
\end{enumerate}
